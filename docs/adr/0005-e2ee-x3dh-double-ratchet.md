# 0005. Сквозное шифрование на X3DH и Double Ratchet, только libsodium

## Контекст

Сервер не должен читать переписку, а сообщения должны доходить офлайн и приходить в произвольном порядке после пропусков.

## Решение

Личные чаты шифруются по X3DH с проверкой подписи одноразового ключа и по Double Ratchet. Все примитивы берутся из libsodium: X25519, Ed25519, XChaCha20-Poly1305, BLAKE2b, HKDF и Argon2id. Safety Number строится из identity-ключей двух собеседников.

## Почему

Собственный протокол запрещён и опасен. Один X3DH без ratchet даёт общий секрет, но не даёт forward secrecy после компрометации устройства. Sender Keys предназначены для групп и отложены. Шифрование только на транспорте означало бы, что сервер читает всё. Готовые библиотеки мессенджерного стека тяжелее и хуже ложатся на Qt без лишних зависимостей.

## Последствия

Состояние ratchet хрупкое: потеря файла ключей означает нерасшифровываемые сообщения, и тихого сброса быть не должно. Ограничения на пропуск ключей и срок жизни сессии сужают офлайн-доставку. Смена ключа собеседника требует баннера Safety Number и доверия пользователя. Крипто-тесты, тестовые векторы и фаззинг становятся обязательной частью каждой сборки, а не необязательной проверкой.
