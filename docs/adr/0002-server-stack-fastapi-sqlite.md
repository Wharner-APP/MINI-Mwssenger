# 0002. Сервер на Python 3.12, FastAPI и SQLite

## Контекст

Сервер живёт на домашнем ПК владельца, обслуживает несколько клиентов и должен подниматься одной командой после перезагрузки. Отдельного администрирования и выделенной базы данных нет.

## Решение

Сервер пишется на Python 3.12 с FastAPI и uvicorn; данные — SQLite в режиме WAL; конфигурация — TOML, секреты — только из окружения.

## Почему

Рассматривали Go и Rust: быстрее и экономнее по памяти, но дольше в разработке и сопровождении одним человеком, а узкое место здесь — не пропускная способность. Node даёт лишний рантайм и экосистему. PostgreSQL — отдельная служба со своими бэкапами и весом, избыточная для нескольких пользователей. SQLite — один файл, простой бэкап и достаточная конкурентность при WAL.

## Последствия

Argon2id на входе и крипто-операции ограничивают пропускную способность, поэтому rate limit обязателен. Запись в SQLite плохо масштабируется при росте числа пользователей, а GIL ограничивает параллелизм. Переезд на другой язык или базу затронет протокол, миграции и бэкапы — это не локальная замена.
