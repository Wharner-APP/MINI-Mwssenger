# 0011. Адрес сервера — из README на GitHub при каждом запуске

## Контекст

Сервер стоит за домашним интернетом без белого IP, а внешний адрес туннеля меняется при каждом перезапуске ПК владельца.

## Решение

При каждом запуске клиент скачивает README с GitHub, находит строку туннеля и отпечаток сертификата и сохраняет их. Если GitHub недоступен, используется последний сохранённый адрес, затем ручной ввод. Битый адрес ведёт на экран настройки.

## Почему

Захардкоженный адрес ломается при каждом рестарте. DNS-имя с динамическим обновлением требует домена и дополнительного провайдера. Собственный сервис обнаружения — лишняя инфраструктура. Ручной ввод каждый раз неудобен и провоцирует ошибки. README на GitHub — уже существующий канал публикации, который ничего не стоит.

## Последствия

Доступность мессенджера зависит от GitHub. Компрометация репозитория подменяет и адрес, и отпечаток, поэтому пиннинг в этом сценарии не защищает. Клиент делает запрос к стороннему сервису при каждом старте — это разрешено брифом, но должно быть видно в диагностике. Нужны кэш, понятный офлайн-режим и ручной ввод как последний рубеж.
